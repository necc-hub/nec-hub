## 二、功能可用性逐项评估

### 2.1 门户 Tab（16 个，`web/src/portal/composables/useTabs.ts:4`）

| Tab | 深链 | 门禁 | 可用性判断 | 主要可用性缺口 |
|---|---|---|---|---|
| 我的首页 | `#/home` | 组件内 401 | 🟢 可用 | 组件个性化布局无用户向说明 |
| 我的任务 | `#/my-tasks` | 需登录+绑定 | 🟡 部分 | 飞书 Task v2 需二次授权；`isOverdue` 用模块加载时的 `now` 快照（`MyTasksTab.vue:57`），页面长开逾期判断不刷新 |
| 图纸评审 | `#/drawing-review` | 登录门控 Tab | 🟡 功能最全但体验参差 | 见 2.3 |
| 报销 | `#/reimburse` | 组件内门禁 | 🟡 可用，门禁 UX 最好 | 有登录中/未登录/已登录三态（`ReimburseApp.vue:96-130`），是全站范本；生产支付闭环未验收 |
| 任务排期 | `#/task-schedule` | 无 | 🟡 本地可用 | **数据只在浏览器 `localStorage nec-taskto-v1`**，换设备/清缓存即丢，无跨端同步、无服务端备份；声明里自称 B 级但 `apis: []`，名实不符 |
| 赛季目标 | `#/season-goals` | **无 Tab 门禁** | 🔴 体验最差的一个 | 未登录点进去四个子视图各自报错，401 时直接 `location.href='/'` 整页跳走（`store.ts` api 封装），用户会被弹回首页且丢失上下文 |
| 应用广场 | `#/apps` | 无 | 🟢 可用 | 同功能多入口易混淆（见 2.4） |
| Skill 中心 | `#/skills` | 无（更多组） | 🟢 可用 | 线上 22 个，README 写 21 个，文档滞后 |
| 资料页 | `#/docs` | 无（更多组） | 🔴 手册入口名不副实 | 详见第四节 |
| 开源仓库 | `#/repos` | 无（更多组） | 🟢 可用 | — |
| 硬件评审 | `#/hardware-review` | 登录门控（更多组） | 🟡 可用 | 藏在「更多 ▾」里，与"核心流程"定位不符；附件映射历史缺陷需回归验证 |
| 合同审批 | `#/contract-approval` | 登录门控（更多组） | 🟡 可用 | 同上；独立页未登录时无跳转按钮，只显示"请回到门户首页登录" |
| 数据看板 | `#/dashboard` | 角色脱敏 | 🟡 可用 | 依赖 dashboard 配置；财务区按角色显隐 |
| PRD 看板 | `#/prd` | 无 | 🟢 可用 | 状态靠 Agent 手动 `update_prd`，可能漂移 |
| NEC-MCP | `#/agent` | 无 | 🟢 可用（说明页） | 30 工具说明，面向开发者 |
| 管理 | `#/admin` | 角色门控 | 🟡 可用 | 唯一有集中配置状态视图的地方（`AdminTab.vue:296-364`） |

**结构性问题：门禁策略三套并行**
1. Tab 级隐藏（`GATE_TABS`：图纸/硬件/合同）——未登录连入口都看不到；
2. 组件内门禁（报销）——入口可见，内部给登录引导，体验最好；
3. 无门禁裸奔（赛季目标、任务排期、我的任务）——点了才报错或跳走。
同一站内三种心智模型，新用户无法预期"点进去会怎样"。

### 2.3 图纸评审（投入最多，值得单独说）

实际 UI 与文档描述的差异：

| 文档说法 | 代码事实 | 位置 |
|---|---|---|
| 右上角「＋ 提交评审单」按钮 | 实际是顶部 nav 的「提交」Tab | `DrawingReviewApp.vue:42,90` |
| 「🔄 加载默认值」按钮 | **没有这个按钮**，`loadDefaults()` 在 `onMounted` 自动执行且只填空白字段 | `SubmitView.vue:81-91,113` |
| ↑↓ 键选择联想、Enter 确认 | **无键盘导航**，只有 `onDocClick` 点外部关闭 + 鼠标点击选中 | `SubmitView.vue:55-69,178-196` |
| 文档未提 | 项目+机型确定后自动算下一版本号（500ms 防抖，手改不覆盖） | `SubmitView.vue:93-108` |
| 文档未提 | 设计负责人默认当前登录人，可展开代他人提交 | `SubmitView.vue:110-114` |
| 文档未提 | 图纸文件 10MB 校验 + 上传进度，上传中禁止提交 | `SubmitView.vue:120-128` |

**即最有价值的三项能力（版本号联动、登录人预填、上传防呆）手册里一个字没写；手册重点教的两项（默认值按钮、键盘操作）在代码里不存在。**

另：门户内嵌与独立页现已共用 `DrawingReviewApp.vue`（`embedded` prop），旧报告的"双实现漂移"已解决。但**详情视图 `router()` 仍是纯内存切换，无 URL 同步**——刷新详情页回列表、无法把某张评审单链接发给同事，这对评审协作是实质性障碍。

### 2.4 入口冗余（用户侧最直观的困惑）

线上 `/api/apps` 共 32 条，其中同一功能出现多次：

- `drawing-review`（内置，B/partial）与 `drawing`（内置，已废弃）与 R2 的 `drawing`（`drawing.newenergycoder.club`）——**三个"图纸"入口**
- `reimburse`（内置）与 R2 的 `reimburse`（`reimburse.newenergycoder.club`）
- `domains`（内置）与 R2 的 `domains`（`domains.newenergycoder.club`）
- `nec-hub-portal`（门户自己的镜像也作为一个应用列在应用广场里）

应用广场按 `source === 'builtin'` 分三组（`AppsTab.vue:13-15`），外部/R2 应用全堆在"队员上架应用"，于是**废弃应用、镜像应用、社区作品混在同一区**，没有任何"推荐入口"标识。

### 4.3 已有手册本身的质量问题

1. **覆盖率严重偏科**：图纸评审一个功能占了 12 篇（用户手册/快速开始/FAQ/特性/开发/架构/扩展/API/部署/故障/监控/安全），其余 13 个内置应用合计只有 3 篇配置手册。报销、硬件评审、合同审批、赛季目标、域名分发、任务排期——**用户向手册为零**（域名分发有《域名分发系统使用手册.md》但未上线到资料页）。
2. **内容与实际 UI 脱节**：见 2.3 表格，图纸评审手册描述的按钮和键盘操作在代码里不存在。
3. **指标无出处**：手册宣称"减少 60% 填写时间 / 降低 40% 输入错误 / 提升 80% 数据一致性"，`文档目录索引.md` 宣称"完整性 100% / 准确性 100% / 功能覆盖 100%"——均无测量依据，且与实际不符。
4. **索引自指过时**：`文档目录索引.md` 标题是"图纸评审系统 - 文档目录索引"，只列 12 篇、日期停在 2026-10-14，而 `docs/` 已有 56 篇。它自称"全站文档导航"，实际只是单功能导航。
5. **根目录散落临时文档**：`REIMBURSEMENT_GUIDE.md`、`TEST_REIMBURSE_GUIDE.md`、`REIMBURSE_TEST_RESULT.md`、`REIMBURSEMENT_SUMMARY.md` 四篇是 2026-10 的手工 curl 测试记录（教用户复制 `nec_session` Cookie 用 curl 提交），已被报销助手 UI 取代，且**引导普通用户复制会话 Cookie 是不该出现在使用手册里的做法**。
6. **历史报告未标注时效**：`页面与Tab状态现状.md`（2026-10-14）描述的"全站仅 3 个 HTML / public/portal 原生 JS / 硬件评审无前端"已完全不成立，但文件没有任何"已过时"头注，新人读了会建立错误心智模型。

## 五、建议的使用手册体系（可执行方案）

### 5.1 目标结构：一个入口、三层深度

```
门户「资料页」改为「帮助中心」（或保留资料页，新增 #/help）
│
├── L0 新用户 5 分钟（1 篇，必须放线上）
│     登录 → 我该用哪个 Tab → 三个最常见任务各一条链接
│
├── L1 按角色的任务手册（4 篇）
│     队员：提交图纸评审 / 提交报销 / 看我的任务 / 申请域名
│     组长：赛季目标收集与采纳 / 多维表字段规范 / 数据校验
│     队长·财务：审批处理 / 报销台账 / 周报 / 会话管理
│     维护者：模块配置 / 应用上架 / 资料发布 / MCP 接入
│
└── L2 单功能参考（每应用 1 篇，与 integration.json 同目录）
      web/apps/<name>/README.md  →  构建期汇总到帮助中心
```

**关键机制建议**：把每应用的手册放在 `web/apps/<name>/README.md`，与 `integration.json` 并列；`vite.config.ts` 的 `builtinAppsManifest()` 已经在构建期读 `integration.json` 了，顺手把 `manualUrl` 一起下发，**手册与应用同生命周期、同 review、同部署**，从机制上杜绝"手册描述了一个不存在的按钮"。

### 5.2 落地顺序

| 步 | 动作 | 工作量 | 收益 |
|---|---|---|---|
| 1 | 修 KV 注册表：VI 手册 V1.0 → V1.1；6 条空 url 条目撤下或补内容；报销 SOP 指向 `#/reimburse` | 0.5h（需 MCP/管理员权限） | 消灭 404 与死占位 |
| 2 | `SEED_DOCS` 加注释说明"仅首访生效，线上修改须走 publish_doc" | 10min | 防止反复踩坑 |
| 3 | 根目录 4 篇报销测试记录归档到 `docs/archive/`，或删除 | 10min | 去掉误导性手册 |
| 4 | `页面与Tab状态现状.md`、`NEC-HUB_模块优化评估报告_V1.0.md`、`文档目录索引.md` 加"历史快照，以代码为准"头注 | 15min | 防止错误心智模型 |
