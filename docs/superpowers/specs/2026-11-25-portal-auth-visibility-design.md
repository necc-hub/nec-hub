# 门户登录可见性设计

- 日期：2026-11-25
- 状态：已确认边界，待书面规格复核
- 范围：NEC Hub 门户；不包含 R2 子应用、外部应用或托管接口的新增鉴权。

## 1. 目标与口径

未登录访客看不到需要登录才能查看的内部页面及其入口，也不因常驻挂载而发起内部业务数据请求。登录后按原角色恢复；管理页保持现有角色限制。隐藏是展示和加载边界，不替代后端鉴权。

### 登录可见

我的任务、报销、图纸评审、硬件评审、合同审批、任务排期、赛季目标、数据看板。

### 公开

首页、应用广场、Skill 中心、资料页、开源仓库、PRD 看板、NEC-MCP。R2 子应用与外部应用沿用原可见性和权限。

### 管理可见

管理页沿用 `canAccessAdmin()`，只有已登录且角色满足现有管理条件的用户可见。

## 2. 导航、组件与深链

在 `useTabs.ts` 中维护唯一的登录门控集合，导航和深链共用 `gateVisible()` / `isTabVisible()`。

登录状态尚未确认（`auth.phase !== 'ready'`）时不将访客判定为已登录，受限组件不挂载。`App.vue` 只对当前活跃页面挂载组件，离开页面时卸载其内容；这样未登录没有受限组件的隐藏 DOM 或后台业务请求，登录后原组件正常加载。

未登录访问受限 hash 时停留公开首页，暂存目标并显示明确登录提示，不直接展示内部内容。登录成功后沿用 `pendingHash` 与 `replayLoginReturn()` 恢复目标。未知 hash 仍回首页。

主动登出时，若当前处于受限页面则切回公开首页；若当前在公开页面则停留原处。「更多」仅在至少一个可展开的公开入口存在时显示。

Hero 的内部任务 CTA 改为公开的应用入口；访客不能通过 Hero 按钮绕过门控。首页布局编辑、恢复默认、拖拽、个人视图标识及任务/报销/目标/物资组件仅登录显示。访客首页保留公开应用、资料及团队动态，不显示“请登录”的占位业务卡。

`GoalBanner`、`TodoBar` 及首页快捷待办在访客状态不展示、不请求业务数据；登录后恢复正常加载。

## 3. 权限与错误处理

不修改后端 API 权限、不复制角色判断到组件、不扩大 R2 或外部应用的公开范围。前端隐藏仅用于消除无权限入口与无效业务请求，后端现有 401/403 仍是最终边界。

登录失败、会话过期或主动登出统一回到公开可见状态。恢复深链时再次检查权限；管理深链不会因普通成员登录而放开。

## 4. 验证

- 模型测试：公开/登录/管理页面的可见性、深链暂存、登录恢复、登出回落。
- 组件契约测试：登录初始化前及未登录时不挂载受限内容，不渲染受限首页组件或业务横幅，不暴露编辑布局入口。
- 全量 Vitest、TypeScript、生产构建。
- 本地 Worker 浏览器验收：未登录桌面/移动导航与首页，深链回落，登录控件可用；无内部业务请求或受限页面闪现。
- 真实 OAuth 登录后逐角色验证需要在可用的测试会话中进行；不得为了验收创建、修改或删除生产业务数据。
