# NEC Hub 移动端与门户视觉改版设计

- 日期：2026-11-22
- 范围：`hub.newenergycoder.club/#/home`、应用广场及门户公共页眉
- 技术栈：Vue 3、Tailwind CSS 4、现有 Cloudflare Workers 静态构建
- 依据：线上 1440px / 390px 页面审查、CANDYSIGN 制糖工厂官网、NEC VI V1.1

## 1. 目标与原则

将门户从均质的通用后台调整为“品牌主视觉 + 编号产品型录 + 高效率团队工作台”。借鉴制糖工厂的主视觉聚焦、编号目录和克制留白，但不引入电商购买流程，不牺牲成员处理任务的效率。

按用户已确认的顺序实施：

1. 修复移动端截断、逾期摘要和文字对比度。
2. 重构首页 Grid、字体层级、卡片和色彩。
3. 重做应用广场编号目录和品牌主视觉。

成功标准：

- 390px 视口无页面级横向溢出，任务状态、日期、账号入口可访问。
- 多条目标告警默认只显示一条摘要，完整条目可展开和收起。
- 正文及关键元数据使用 VI 规定的墨青或次级灰，普通文字对比度不低于 4.5:1。
- 首页桌面端为明确的工作区 / 辅助区双栏，移动端按任务优先级单列。
- 应用广场三个分组共用一套编号目录行组件，保留现有链接和集成信息。
- 首次访客获得完整品牌 Hero，登录用户和回访访客保留紧凑模式。
- 现有首页个人 / 组 / 默认布局、拖拽排序、登录门控、深链和 Tabs 常驻挂载行为不回归。

## 2. 方案取舍

### 采用：渐进式门户重构

保留数据层、路由和组件白名单，替换公共视觉 Token、页眉、告警、首页布局和应用目录。优点是可以分三阶段验证，回归范围可控，也最符合现有 VI。

### 不采用：营销官网优先

把首页整体改为大幅摄影和长篇品牌叙事会有更强展示性，但会增加成员进入任务的滚动成本，且当前缺少统一摄影资产。

### 不采用：纯工具极简改版

只修 CSS、不建立 Hero 和目录语言，实施最快，但无法解决门户辨识度不足的问题。

## 3. 设计系统

### 3.1 色彩与表面

沿用 NEC VI V1.1，不修改品牌标志和现有语义色：

- 正文 / 标题：`--nec-ink` / `--nec-navy`。
- 次级文字：`--nec-gray`，禁用 `gray-300/400` 承载有效信息。
- 主交互：藏青实底白字；破晓青只用于短粗文本、焦点、编号和地平线。
- 页面底色：门户专用暖纸色 `#FAF7F2`，作为中性背景，不替代品牌 Token，不用于状态表达。
- 内容表面：纸白、1px `--nec-line`、统一 12px 或 16px 圆角。
- 阴影仅用于健康面板、下拉层和弹窗；普通内容卡使用边框和分隔线。
- 状态只使用 `--nec-success/warning/danger/info` 及其浅底，不新增语义色。

### 3.2 字体与层级

沿用 VI 字体栈，不引入新的网络字体：

- Hero 英文：桌面 64–80px，移动 40–48px，展示字重。
- 页面标题：桌面 28–32px，移动 24–28px。
- 分区标题：20–24px；正文 14–16px。
- 元数据：12–13px，但使用可读前景色。
- 编号、日期、计数：`--nec-font-mono`，使用 tabular numbers。

### 3.3 动效与可访问性

- 悬停和展开使用 160–240ms，只改变颜色、边框、位移和小于 1.03 的缩放。
- 所有新增展开按钮提供 `aria-expanded` / `aria-controls`。
- 新增交互具备可见 `:focus-visible`，移动端主要触控目标至少 44px。
- 尊重 `prefers-reduced-motion`，不使用视差、粒子或自动轮播。

## 4. 第一阶段：移动可用性、告警与对比度

### 4.1 页眉与导航

`HeroHeader.vue` 改为清晰的两层结构：品牌区与操作区在窄屏可换行，所有 flex 文本容器具有正确的 `min-width: 0`；不再让账号登录被挤出视口。`UserBox.vue` 在移动端隐藏次要说明，保留登录 / 账号入口，密码表单可纵向换行。

`TabNav.vue` 保持横向滚动，但增加滚动容器边界、活动态可见性和末端渐隐提示；不通过压缩字号或截断标签解决拥挤。

### 4.2 逾期目标摘要

`GoalBanner.vue` 默认显示单行摘要：

- 总目标数、逾期数、最大逾期天数。
- 一个最高优先级条目的短标题。
- “查看详情”展开完整目标列表，展开后可收起。
- 关闭按钮继续调用现有 `dismissGoalBanner`，签名和 T-3 强制重弹逻辑不变。

摘要计算提取为无副作用函数，输入现有 `GoalItem[]`，输出展示模型。摘要主条目优先选择逾期最久者；无逾期时选择 `daysLeft` 最小者；并列保持源数组顺序。无逾期时只显示临近节点计数；无数据时仍由现有 `v-show` 隐藏。危险态使用浅危险底和深红文字，不再默认使用整片红底白字。

### 4.3 任务、动态与目标行

- 任务行在窄屏使用两行：标题允许两行换行，状态与日期在第二行，不使用单行截断隐藏关键信息。
- 团队动态窄屏隐藏作者时间等次要元数据到第二行，主链接可换行，不撑破容器。
- 目标行在窄屏重新排布日期、进度和链接，避免多个 `shrink-0` 挤压标题。
- 所有加载失败、空态、同步时间和说明文字切换到 VI 次级灰。

## 5. 第二阶段：首页 Grid 与视觉系统

### 5.1 页面壳

`App.vue` 中首页与应用广场使用最宽 1280px 的门户版心；文档和阅读型 Tab 保持现有 `max-w-5xl`，数据看板保持宽版。所有 Tab 仍常驻挂载并用 `v-show` 切换。

### 5.2 首页结构

将 `HomeTab.vue` 的 CSS columns 改为显式 Grid：

- 桌面主栏：我的任务、我的报销、赛季目标、物资查询。
- 桌面辅助栏：我的应用快捷区、常用资料。
- 团队动态独立位于工作组件之后；移动端位于任务和目标之后。
- 保留后端返回的组件顺序作为各栏内部顺序，保留拖拽排序和保存逻辑；分类只负责视觉区域，不修改持久化布局 schema。

实现时采用两个明确的 Grid 区域，组件按 id 归入工作区或辅助区，各区内保持原数组相对顺序。拖拽仍操作原数组并使用原索引保存，但只改变同区内的顺序；跨区拖动不改变组件归属，编辑提示同步说明这一规则。这样既保留现有持久化 schema 和同区排序能力，也避免 CSS columns 的跨栏阅读顺序。`grid-template-areas` 或明确的 grid placement 只承担表现。

首页页头降低“编辑布局”的视觉权重，恢复默认仅在登录后显示；“全员默认”显示为“团队视图”，数据来源和同步时间仍可辨识。待办计数、加载、空态和 Prompt 编辑面板保留。

### 5.3 卡片

新增门户通用类统一卡面、标题、元数据和分隔线，优先在首页和应用广场使用，不批量改写独立业务应用。普通卡无阴影，hover 只提高边框和轻微底色变化；编辑手柄和移除按钮继续可用，并在触屏编辑模式下不依赖 hover 才能发现。

## 6. 第三阶段：应用编号目录与品牌主视觉

### 6.1 应用目录组件

新增应用目录行组件，`AppsTab.vue` 的核心流程、独立应用、队员上架应用三个分组都传入同一组件。每行包含：

1. 两位等宽编号，编号在每个分组内从 01 开始。
2. 统一比例视觉缩略图。
3. 完整应用名、一句用途和集成徽章。
4. 队员应用保留作者、版本、更新时间和双版本提示。
5. 整行使用现有 URL；内置链接和外链的打开方式保持原行为。

缩略图优先复用仓内已有 K1、6014、RESS 静态图片；其余应用使用本地 CSS / SVG 工程图形和应用名称首字生成一致封面，不请求第三方图片，不复制制糖工厂素材。图片加载失败时隐藏图片并显示几何 fallback，不影响链接和文字。

发布 Prompt 面板保留 `publish-box`、`publish-prompt` 和复制逻辑。`apps-list` 继续标记队员应用列表。集成徽章仍统一由 `IntegrationBadge.vue` 输出。

### 6.2 首页应用快捷区

首页不展开完整目录，只保留最多 6 个应用的紧凑入口。复用目录的视觉模型和可读名称，不重复维护缩略图逻辑；最近使用排序和 localStorage 记录不变。

### 6.3 品牌 Hero

完整 Hero 使用现有 NEC 矢量标志、蓝图网格、双圆破晓太阳、地平线和抽象模块几何，形成“破晓工作台”，不引入摄影依赖。左侧为 `BUILT TO DAWN`、中文口号、两个明确入口；右侧为静态 SVG 构图。完整模式控制在约 50–60vh 的内容区间，不做强制全屏滚动。

紧凑模式保留现有 `heroCompact()` 判断，只展示品牌细条、状态和账号，不显示大型构图。实现时在 `auth.phase` 进入 `ready` 后才调用 `heroCompact()`，避免首次读取写入 `nec_hero_seen` 导致首访被错误压缩；健康检查请求、面板、登录流程及返回深链不变。

## 7. 数据、状态与错误处理

- 不修改 `/api/home`、`/api/apps`、`/api/dashboard`、`/api/todos` 的响应结构。
- 不修改首页布局 KV、应用 manifest、登录 Cookie 或 localStorage key。
- 所有现有加载中、空态、接口失败降级均保留，文字对比度同步提升。
- 应用封面失败只影响装饰图；告警摘要不改变原始 `goalBanner.items`，展开列表仍直接使用源数据。
- 无新增网络请求、第三方脚本或运行时依赖。

## 8. 测试策略

遵循现有 Vitest Node 环境，先写失败测试，再实现。

### 自动化

- 目标摘要纯函数：空列表、全部临近、部分逾期、多个逾期、最大逾期天数和标题选择。
- 组件契约：三分组复用目录行、集成徽章只保留一个共享实现、发布面板和关键 DOM id 保留。
- 首页契约：白名单组件、拖拽保存和 Tabs 常驻相关现有测试全部保留。
- 可访问性结构：摘要展开按钮的 ARIA 关系、装饰图隐藏、应用图片 alt 与失败 fallback。
- 运行相关 Vitest、全量 `npm run test:ci`、`npm run check` 和 `npm run build:web`。

### 浏览器验收

使用本地 Vite 与可用的线上数据快照或实际线上只读页面检查：

- 1440×1000：首页双栏、应用目录、完整 / 紧凑 Hero。
- 390×844：页眉、导航、告警展开、任务 / 目标 / 动态、应用目录。
- 768×1024：中间断点无异常空栏或溢出。
- 检查 console、网络失败降级、键盘焦点和 reduced-motion。

## 9. 明确不做

- 不改后端 API、数据库、权限和部署配置。
- 不重写其他业务 Tab，不统一替换所有独立应用的内部视觉。
- 不新增搜索、筛选、收藏、轮播或分析功能。
- 不修改 NEC 标志、品牌字体和 VI 语义色。
- 不部署、不提交、不推送，除非用户另行明确要求。
